## 二、P0：会让用户拿到错误结果

### P0-1 向量编码器缺失时整条链路 500（已修）

- **现象**：本机 `data/processed/vectors.npz» 存在但 `FlagEmbedding» 未安装。启动钩子里的
  `vindex.encode(["预热"])» 被 try/except 包住所以**启动成功**，但每次提问都在
  `retrieval/vector_store.py:102» 抛 `ModuleNotFoundError»，被全局异常处理器兜成 500。
- **根因**：`hybrid.py:56» 用 `self.vector.mat is not None» 判断"向量通道可用"。
  npz 里只存**历史条款向量**，查询侧仍要现算 query 向量 —— 矩阵在 ≠ 通道能用。
- **证据（修复前，实跑）**：

```
docs: 406
vector load: True stats: {'size': 406, 'dim': 1024, 'loaded': True, 'backend': 'numpy-local(npz)'}
encode FAIL: No module named 'FlagEmbedding'
  File ".../retrieval/vector_store.py", line 55, in encode
    out = self.model.encode(...)
ModuleNotFoundError: No module named 'FlagEmbedding'
```

- **修复**：新增 `encoder_ready()»（失败一次即记住，不每条查询重试 import）；
  `VectorIndex.search» / `MilvusStore.search» / `HybridRetriever.search» 三处都先判它，
  不可用就关掉这条通道，检索降级 BM25 单通道，服务继续可用。
- **证据（修复后，实跑）**：

```
[vector] 编码器不可用，关闭向量通道: No module named 'FlagEmbedding'
--- 平台内经营者是什么意思 | lvl L1 | handoff False | gen template | 4ms
    top: 电子商务法第九条 score=0.01639
```

### P0-2 低置信阈值用错口径，降级链路上"每个问题都答没有依据"（已修）

- **根因**：`service/qa.py» 的 `low_conf_threshold()» 在无精排时一律返回 `0.02»。
  但 RRF（k=60）的真实取值是：两通道都命中 rank0 = `2/61 ≈ 0.033»，**单通道 rank0 = `1/61 ≈ 0.016»**。
  向量通道一关，连最相关的第一条都低于 0.02 → 全量判低置信 → 用户看到"未检索到依据"。
- **修复**：阈值按实际活着的通道数取（≥2 通道 0.02，单通道 0.010），推导过程写进注释。
- **证据**：修复后 `score=0.01639 > 0.010»，正常给出条款与结论。

### P0-3 引用校验漏掉两段式平台编号（已修）

- **根因**：`generation/answer.py» 的 `PLATFORM_NO_RE» 是 `{2}»（三段式 `2.3.1»），
  而平台规则里 `2.3»、`4.2»、`5.1» 全部真实存在。结果是**编造一个两段编号，闸门永远拦不住**。
- **修复**：改为 `{1,2}» 段并加 `(?![\d.%])» 排除小数/百分号；判定从"严格等值"改成"层级同族"
  （`2.3» 与 `2.3.1» 互认），避免两段编号一放进来就大量假阳性。
- **证据**：同评测集、同数据，`法规检索» 层引用准确率 68.9% → 72.5%。

### P0-4 时限类答复里没有时限（已修）

- **现象**：问"我多久要处理"，答复正文是条款首句摘录，而时限常常在第二句。
  用户拿到一段"相关规定如下"，最关键的那个数字不在里面。
- **修复**：`compose()» 在结论末尾补「本条时限：…」。L3 也给 —— L3 的含义是
  "处罚结果不由 AI 判定"，不是"什么都不说"。
- **证据**：`时效正确率(端到端)» 73.3% → 85.0%，`时效一致性» 100%。

### P0-5 时限提取单位不全（已修）

- **根因**：`nlp/router.py» 的 `TIMEOUT_RE» 只认 `日/天/小时/工作日/个月»，
  `保存三年»、`四个星期内»、`30 分钟»、`十个自然日» 全部丢。
- **修复**：补齐单位；`(?!\d{3,})» 挡 4 位年份（`自2023年5月1日» 不是时限）；
  `(?!岁)» 挡"十四周岁"被截成"十四周"（生成评测集时实测到的真错）。
- **关键纪律**：评测集不再自带一条正则，直接用 `nlp.router.TIMEOUT_RE»。
  两边各写一份就是两套定义，测出来的数和用户看到的字段不是一回事。

### P0-6 `t_clause.content_hash» 全是空串（已修）

- **现象**：406 条条款的 `content_hash» 全部是 `""»（`pipeline/build_sqlite.py:166» 写死的空值），
  这张表的"变更检测"能力从设计上就是空的。
- **修复**：`change_pipeline.py --backfill-hash» 补基线；流水线每次跑也会先补。

### P2-4 的实测证据（这条最值得看）

补了 120 条 FAQ 的同义问法（每条 +3 条，从自己的 keywords 套问法框架，不编事实），
用 12 条**手写口语探针**在增强前后各跑一遍：

```
[增强前] buyer     Top1 命中 8/8  过 0.88 阈值 0/8
[增强后] buyer     Top1 命中 8/8  过 0.88 阈值 0/8
[增强前] merchant  Top1 命中 4/4  过 0.88 阈值 1/4
[增强后] merchant  Top1 命中 4/4  过 0.88 阈值 1/4
```

个别条目 sim 有微动（0.270 → 0.276、0.393 → 0.472），但**没有一条跨过 0.88**。

**这说明问题不在同义问法，在阈值口径**：
`sim = Σ(idf·命中) / Σ(idf·查询词)»，分母是**查询**的全部词。
口语问句里的"我下单了""大概""好几天"这些词在 FAQ 库里根本不存在，
分母里带着它们，覆盖率天然到不了 0.88。
于是：**Top1 全对（12/12），却没有一条会走 FAQ 直答** —— 四级漏斗的第一级在真实口语下近乎空转。

- 建议（需运营确认，不是纯代码题）：改**相对判据**，例如
  `top1.sim ≥ 0.88» 或 `top1.sim ≥ 0.30 且 top1.sim − top2.sim ≥ 0.15»；
  分母只取"查询里能在库词典命中的词"。
- 为什么这次不改：它直接改变"机器人回不回答"这一产品行为。按项目自己的纪律
  （"阈值必须和分数口径绑定"），改之前必须用正负样本集标定；
  现在手上只有 12 条正样本、没有负样本集，贸然改就是把一个问题换成另一个问题。
