4关键分工：哪些必须你做

我能独立完成（约 80%）

  • 全部代码：切分器、元数据提取、检索、融合、重排、风险路由、引用校验、变更流水线
  • 建表 / 建 collection / 索引 / 缓存规范
  • 合成业务数据（商家 50 / 店铺 50 / 订单 5000 / 售后单 800）
  • 评测集候选生成、回归脚本、指标看板
  • 派生数据：README、演示脚本、简历段落、追问手册
  • 条款解析：把你放进 data/raw 的原文自动切成条款树

必须你本人做（已缩到最小）

  • 验收条款切分：确认条款数与官方条数一一对上（89/56/63/75）
  • 判断问题真实度：我生成的评测题草稿，你判断"商家真会这么问吗"
  • 平台规则（可选）：四大平台规则中心 JS 渲染 + 风控，抓不到正文，只能人工录入；不做则该层留空
  • 演示演练：现场讲的人和写代码的人必须是同一个
  • 方向判断：指标达不到时，选择"继续优化"还是"改叙述"

2026-10-29 更新：法规原文已由 AI 联网获取（全国人大 / 市场监管总局），订单数据已合成 5000 条，本条原"用户下载法规"要求作废。

原因：技术上是风控与登录态限制；可信度上是"我读过规则"本身就是面试的可信度来源。无 source_url 的条款一律不入库。
