# 16 · 接口与数据模型变更清单（v8 → v12）

> 供前端对接与排查用。按「表结构 / 接口 / 返回字段」三类汇总 v8 之后新增的变更，
> 不再需要靠读代码反推。当前版本线：v12。

## 一、数据表变更

### t_faq（知识库，v8 / v11 两次）
| 列 | 版本 | 说明 |
|---|---|---|
| `shop_id INT NULL` | v8 | `NULL`=平台通用基线，非空=该店专属；规则/治理域强制为 NULL |
| `reviewed_by INT NULL` | v11 | 审核人 id（沉淀审核流） |
| `reviewed_at DATETIME` | v11 | 审核时间 |
| `review_note VARCHAR/TEXT` | v11 | 审核意见（驳回原因等） |
| `cat_scope VARCHAR(64) DEFAULT ''` | v11 | 类目作用域：空=平台通用；非空=该品类店铺共用模板（`shop_id` 须为空） |

### t_order（订单，v8）
| 列 | 说明 |
|---|---|
| `item_title / sku / qty / unit_price` | 商品明细（单行字段，多商品见子表） |
| `carrier / tracking_no / picked_at` | 承运商 / 运单号 / 揽收时间 |

### t_order_item（订单商品子表，v10 新增）
`order_no, line_no, title, sku, qty, unit_price, refund_qty, refund_amount, category, created_at`
- `UNIQUE(order_no, line_no)`，支持一单多商品、部分退款（`refund_qty`/`refund_amount`）。
- `order_detail` 的 `items` 主口径由此表来，主表单行字段退为回退。

### t_appeal（申诉，v12 新增列）
| 列 | 说明 |
|---|---|
| `supplement_count INT DEFAULT 0` | 补充材料次数（上限 `APPEAL_MAX_SUPPLEMENT=2`） |
| `supplement_history TEXT` | 补充历史 JSON：`[{at, note, added}]` |
| `review_deadline DATETIME` | 人工复核时限（进入 human_review 时设 `APPEAL_REVIEW_HOURS=72h` 后） |

## 二、新增 / 变更接口

### 智能客服（api/cs.py）
| 接口 | 版本 | 说明 |
|---|---|---|
| `GET /api/cs/cases` | v9 | 带单核查案件列表（仅 ops/admin，在办优先） |
| `POST /api/cs/sessions/{sid}/case` | v9 | 带单核查，body `{dispute_id}`，返回 `case_brief`（只给事实与条款、不下结论） |
| `GET /api/cs/board` | v9 | 返回体新增 `ui` 对象（见下） |
| `GET /api/cs/faq/pending` | v11 | 待审队列（仅 ops/admin） |
| `POST /api/cs/faq/{fid}/review` | v11 | 审核通过/驳回，body `{approve, note}` |

#### `board.ui` 结构（v9，板块外观与动作由服务端下发）
```json
{
  "avatar": "客", "badge": "平台规则助手", "intro": "...",
  "greet": "引导语", "trace": "正在加载...", "placeholder": "输入...",
  "states": {"bot": "在线", "human": "人工坐席中"},
  "actions": [ {"kind": "escalate", "label": "平台介入", "title": "..."} ],
  "can_escalate": true
}
```
- `actions` 里 `kind=escalate` 只在 `scope=shop` 且 `role=buyer` 时出现；治理板块只给「仲裁台/规则库」链接。
- 前端只认 `can_escalate` 决定是否画「申请平台介入」链路，不再自己判断角色。

### 平台监管（api/gov.py）
| 接口 | 版本 | 说明 |
|---|---|---|
| `POST /api/gov/penalties/expire` | v10 | 手动触发罚单到期回收（`suspend_until` 落地） |
| `POST /api/gov/appeals/{aid}/supplement` | v12 | 补充材料，body `{evidence, note}`，处理中追加并重初审 |
| `POST /api/gov/appeals/{aid}/reopen` | v12 | 二次复核，body `{evidence, note}`，被驳回后复议一次 |
| `GET /api/gov/appeals` | v12 | 返回体新增 `supplement_count / supplement_history / overdue_hours` |

## 三、返回字段变更

### `order_detail`（service/gov.py，v10）
- 主口径改为 `items`（数组，含 `refund_qty`/`refund_amount`），`item` 保留为首行别名。
- 新增：`item_count / qty_total / subtotal / amount_mismatch / refunded_qty / refunded_amount`。
- `logistics` 新增 `trace`（v12，物流轨迹节点数组 `[{time, status, desc}]`，由 `service/logistics.py` 提供，默认本地模拟器，`LOGISTICS_PROVIDER` 可切真实接口）。

### `case_brief`（service/gov.py，v9 / v10）
- 返回 `{dispute_id, dispute_no, dtype, text, related}`。
- `related`（v10）：按本案事实在全量 406 条条款里检索出的相关条文，`[{doc, clause, path, content, scene, score}]`，附「相关度≠适用」声明。
- 多商品订单逐行列出，标出已退件（v10）。

## 四、其他可配置项（环境变量）

| 变量 | 默认 | 说明 |
|---|---|---|
| `PENALTY_SWEEP_SEC` | 600 | 罚单到期巡检间隔（秒） |
| `GOV_APPEAL_REVIEW_HOURS` | 72 | 人工复核时限（小时） |
| `GOV_APPEAL_MAX_SUPPLEMENT` | 2 | 申诉最多补充材料次数 |
| `LOGISTICS_PROVIDER` | local | 物流轨迹来源（local=本地模拟器；预留真实聚合接口） |
