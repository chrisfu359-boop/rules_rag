## 一、本阶段交付内容

### 1. 性能优化（并发瓶颈）
- `common.py`：SQLite 每请求新建连接 → **线程本地连接复用 + WAL + synchronous=NORMAL + busy_timeout**。
- 实测（`tests/concurrency.py`，300 请求/20 并发，真实 HTTP）：吞吐 **44 → 208 req/s（4.7x）**，P95 **2.1s → 150ms（14x）**，P99 6.1s → 160ms。

### 2. 检索与生成调优
- BGE 模型路径改 **D 盘全 ASCII**（`D:/hm_st/EduRAG/code/edu_rag/rag_qa/models/`），避开 Windows sentencepiece 非 ASCII 路径坑。
- 融合权重默认 **BM25 3.0 / 向量 0.5**（`BM25_WEIGHT`/`VEC_WEIGHT` 可覆盖）；精排 **pool=6**（`RERANK_POOL` 可覆盖）。
- 向量+精排全链路实测：引用 **75.4%**、召回@5 **91.4%**、时效 **88.3%**、边界拒答 **100%**（均优于或追平 BM25 单通道 72.5%/91.8%/85%/85%）。

### 3. 数据修复
- `build_sqlite.py`：`t_order` 补 `carrier/tracking_no/picked_at`，新增 `t_order_item` 表，`gen_orders` 生成物流三件套 + 1~3 行订单明细。**种子库现在可确定性重建**（此前重跑会丢物流与明细）。
- **订单生成器数据完整性修复**（数据评审发现的 bug）：金额守恒（先生成明细，订单 amount=Σunit_price×qty，此前 368/5000 不守恒）、主表 qty 与子表首行一致（此前 2475 单不一致）、店铺名对齐 t_shop（此前 87% join 落空）、加 4% 虚假发货正样本（揽收>24h，159 条）。
- 店铺 **3 → 8 家**（补生鲜/美妆/服饰/母婴/运动），`t_shop_credit` 同步。
- **已提交 rules.db 的订单店铺名映射到 8 家 t_shop**（各约 600 单，join 落空 0）。
- 修正 `t_clause id=37`（平台规则 2.2）risk/scene 互换，风险分布恢复 L1 266 / L2 54 / L3 86。
- 清理 `t_cs_session` 里 6 条 e2e 测试残留会话（验收买家），会话 20 → 14。

### 4. 前端
- 右下角**小猫桌宠咨询弹窗**（`web/assets/pet.js`，自包含 SVG，接免鉴权 `/api/demo/ask`）。

### 5. 多轮记忆

### 6. 安全加固
- `/api/gov/orders`、`/api/order/{no}` 加**归属校验**：商家只能查/看本店订单，越权返 404；运营/管理员（平台侧）可查全平台。堵住「任意登录用户枚举别店订单」（多 agent 产品评审指出的风险）。
- **裁决权收回给平台运营**：新增 `ARBITER=("ops",)`，`claim/verdict/can_arbitrate` 改用 ARBITER；管理员（admin）只能查看纠纷、不能裁决，与 `docs/18` 设计一致（此前后端误把 admin 计入 PLATFORM 导致可裁决）。验证：admin claim/verdict 返 403、can_arbitrate=False，ops 正常。
