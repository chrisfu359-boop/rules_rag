# 12 · 接入大模型（填 key 即用）

> 目标：不需要改一行代码，只改 `.env` 就能接任意大模型。不填也能跑（走模板）。

## 一、五分钟接上

### 方式 A：选预设厂商，只填 key（最省事）

打开项目根目录的 `.env`，两行搞定（以 DeepSeek 为例）：

```ini
LLM_PROVIDER=deepseek
DEEPSEEK_API_KEY=sk-xxxxxxxx
```

支持这些预设，换厂商就是改 `LLM_PROVIDER` 这一个词：

| LLM_PROVIDER | 默认模型 | key 申请地址 |
|---|---|---|
| `deepseek` | deepseek-chat | platform.deepseek.com |
| `dashscope` | qwen-plus | bailian.console.aliyun.com |
| `moonshot` | moonshot-v1-8k | platform.moonshot.cn |
| `zhipu` | glm-4-flash | open.bigmodel.cn（flash 免费） |
| `openai` | gpt-4o-mini | platform.openai.com |
| `ollama` | qwen2.5:7b | 本地，不用 key |

### 方式 B：任意 OpenAI 兼容服务（vLLM / 公司内网 / 中转站）

```ini
LLM_BASE_URL=https://your-gateway/v1
LLM_API_KEY=sk-xxxx
LLM_MODEL=your-model-name
```

`LLM_BASE_URL` 要写到 `/v1` 这一层，**不要**带 `/chat/completions`。

### 方式 C：本地 Ollama，完全离线

```bash
ollama serve
ollama pull qwen2.5:7b
```

```ini
LLM_PROVIDER=ollama
LLM_MODEL=qwen2.5:7b
```

### 改完怎么验证（不用重启）

```bash
curl -X POST http://127.0.0.1:8000/api/llm/test
```

返回 `{"ok": true, "model": "...", "ms": 820, "reply": "收到"}` 就是通了。
这个接口会重新读 `.env`，所以填完立刻能测，不必重启服务。

页面顶部的 `大模型` 徽标也会显示当前模型名，没配则显示 `off(模板)`。

## 二、配置项全表

| 变量 | 默认 | 说明 |
|---|---|---|
| `LLM` | `auto` | `off` 强制走模板（用来对比两条路径效果） |
| `LLM_PROVIDER` | 空 | 预设厂商，见上表 |
| `LLM_BASE_URL` | 空 | 显式地址，**优先级高于预设** |
| `LLM_API_KEY` | 空 | 显式 key，优先级高于厂商环境变量 |
| `LLM_MODEL` | 空 | 不填用预设默认模型 |
| `LLM_TIMEOUT` | `25` | 单次调用超时（秒），超时立即降级，不拖住接口 |
| `LLM_MAX_TOKENS` | `600` | 回答长度上限 |
| `LLM_TEMPERATURE` | `0.2` | 合规问答要稳定，别让它发挥 |

优先级：`LLM_BASE_URL/API_KEY/MODEL` 显式值 > `LLM_PROVIDER` 预设 > 厂商同名环境变量。
`.env` 里留空的项会回落到系统环境变量，方便线上用容器注入。

## 三、关键设计：为什么"接上"不等于"写完"

### 1. 引用校验闸门（本项目最该讲的一点）

模型输出 → 抽出所有条款号 → 与本次召回的条款比对：

```
├─ 全部命中      → 采纳，generator = llm:<模型名>
└─ 存在编造编号  → 带着"你编造了第X条"重试一次（temperature=0）
                    └─ 仍编造 → 整条丢弃，退回模板答案
```

**为什么不能"事后把编造的引用删掉"**：删掉条款号，结论本身仍然建立在虚构条款上，
用户看到的是没有出处的断言——比引用错了更危险，因为引用错了至少审计能发现。

实测（`pipeline/test_llm_gate.py`，本地假模型，不花钱）：

| 用例 | 模型调用次数 | 结果 |
|---|---|---|
| 正常回答 + 引用正确 | 1 | 采纳，`llm:mock-model` |
| 编造「第九十九条」 | 2（重试一次） | 拦截，退回模板，记录 `fake_citations` |
| 上游返回 500 | 1 | 降级模板，接口不报错 |

### 2. 三层降级，接口永不 500

```
模型调用失败 → 模板
引用校验失败 → 模板
根本没配置   → 模板（连调用都不发）
```

合规问答不能因为模型欠费或超时就整站不可用。降级后的答案**依然可核对**，不是凑合。

### 3. 缓存 key 带模型名

```python
ck = f"rr:{RULE_VERSION}:faq:{md5(模型名)}:{md5(问题)}"
```

踩过的坑：v4 时只升 `RULE_VERSION`。如果只改 `.env` 换模型不升版本，
旧模型生成的答案会被当成本模型的结果返回。带模型名后换模型自动隔离缓存。

### 4. 冷启动预热

`openai` 包首次实例化约 3 秒（实测首次调用 3.6s，之后 30ms）。
启动时预热 `LLM.client`，否则由第一个真实用户替这笔开销买单。

### 5. 审计可回溯

`t_qa_log` 新增 `generator`、`llm_ms` 两列。事后能查：这条答案是谁生成的、用了多久、
引用了哪几条。出问题时这是唯一能还原现场的证据。

## 四、成本量级（自己乘单价）

一次问答的 token 消耗是固定的，可以自己算：

| 部分 | 量级 |
|---|---|
| system prompt | ~300 token |
| 5 条条款 × 400 字 | ~1300 token |
| 问题 | ~30 token |
| 输出 | ~200–300 token |
| **单次合计** | **约 1800–2000 token** |

按各家定价乘即可，具体价格以官网为准。真正的省钱手段是 **Redis FAQ 缓存**——
高频问题命中缓存时 4ms 返回，不进模型、不花钱（实测截图见 `docs/11`）。

## 五、已知限制（别当成做完了）

1. **无流式输出**。当前是同步返回，首字延迟 = 全量延迟。要流式得改 SSE，前端也要改。
2. **无多轮对话**。每次提问独立成问，不带历史。改造成本在 prompt 拼接和上下文裁剪。
3. **单模型单通道**。没有"主模型挂了自动切备用模型"。
4. **未做输出侧安全过滤**。目前只校验引用，没做敏感词/合规话术过滤。
5. **token 成本未落库**。只记了总量 `total_tokens`，没按请求拆到审计表里做成本归因。

## 六、面试怎么讲这段（30 秒版）

> 检索做完之后我接了大模型，但没停在"调通接口"。
> 我的做法是：模型只允许基于召回的 5 条条款回答，输出后强制做引用校验——
> 抽出来的条款号必须都在召回集里，编造的话带错误信息重试一次，还错就整条丢弃退回模板。
> 因为删掉假引用不解决问题，结论仍然是虚构的。
> 另外做了三层降级，模型超时、欠费、没配，接口都返回可核对的结果，不会 500。
> 缓存 key 里带了模型名，换模型不会串答案。
> 这三个坑我都写了自动化测试，用假模型跑，不花钱。
