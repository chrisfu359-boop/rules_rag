## 三种不要写的表述（写了会被追问穿）

**① 不要写「准确率 95%+」这种没有分母和口径的数。**

- 反例：`问答准确率 95% 以上»
- 为什么不行：口头抽查十几条不能算准确率；而且"准确"本身没定义 —— 是检索对了，还是答案对了？
- 正确写法：`条款引用准确率 72.5%（300 条分层评测集，Top1 命中 gold 条款号；其中法规检索层 70.8%）»

**② 不要写「基于 RAG 提升了大模型准确性」这种因果倒置的话。**

- 反例：`引入 RAG 后模型准确率提升 40%»
- 为什么不行：本项目的模板生成路径根本没用 LLM（`generator=template»），提升来自检索和引用校验，
  不是模型。把功劳记在 RAG 上，面试官一句「你的 baseline 是什么」就崩。
- 正确写法：`引用校验闸门拦截模型编造的条款号：编造即带上"你编造了第X条"重试一次，仍编造则整条退回模板答案»

**③ 不要写「高并发 / 支撑百万级 QPS」这类没压测过的能力。**

- 反例：`系统支撑百万级问询，响应 3ms»
- 为什么不行：`P95 = 3ms» 是在**单机 SQLite + BM25 单通道 + 不调大模型**下测出来的，
  它是"链路开销"，不是"系统容量"。混为一谈就是硬伤。
- 正确写法：`离线问答链路单问 P50/P95 = 1/3 ms（SQLite + BM25，未接大模型）；未做并发压测»

## 面试时最容易被追问的三个数（自己先想清楚）

| 数 | 真实含义 | 被追问时怎么答 |
|---|---|---|
| 引用准确率 72.5% | Top1 是否命中标注的正确条款 | 剩下 27.5% 里跨条款综合层占大头（该层 Top1 40%、召回@5 95%）：两条都召回了，但排不到第一。这是融合排序问题，不是召回问题 |
